## 🔴 Critical — กระทบธุรกิจโดยตรง / กระทบเป้าหมาย SEO หลักของโปรเจกต์

### 1. รูปสินค้าในหน้าหมวดหมู่ SEO (24 หน้า) พังหมดทุกรูป — ยืนยันแล้วบนเว็บจริง
**พบใน:** ทุกหน้าใน `products/<หมวด>/index.html` (24 หน้า เช่น `products/gate-lamp/`, `products/wall-lamp/`, `products/solar-cell/` ฯลฯ) — ตรวจครบทุกหน้าแล้ว บั๊กเดียวกันทั้งหมด

**สาเหตุ:** ไฟล์เหล่านี้อยู่ที่ path `/products/<หมวด>/index.html` จึงต้องอ้างอิงไฟล์อื่นด้วย `../../` (เช่น `../../css/style.css`, `../../images/logo-nav.png` ซึ่งทำถูกแล้ว) แต่ **รูปสินค้าในการ์ดสินค้ากลับใช้ path แบบไม่มี `../../`** เช่น:
```html
<img src="images/products/exterior/gate-lamp/36-5180S2-BG.webp" ...>
```
ทำให้เบราว์เซอร์คำนวณ URL ผิดเป็น `/products/gate-lamp/images/products/exterior/gate-lamp/...` (ซ้อน path ตัวเอง) ซึ่งไม่มีไฟล์อยู่จริง

**ทดสอบจริงแล้ว (เปิดเว็บจริง + เช็คผ่าน JS ในเบราว์เซอร์):**
```json
{"totalCards":115,"brokenCount":115}
```
รูปสินค้า **115/115 ชิ้นในหน้า gate-lamp พังหมดทุกรูป** (naturalWidth: 0, complete: false) และเช็คโค้ดอีก 4 หมวด (wall-lamp, solar-cell, high-bay, accessories) พบ pattern เดียวกันหมด — สรุปว่า **รูปสินค้าใน 24 หน้าหมวดหมู่พังทั้งหมด (792 รูป)**

**ผลกระทบ:** นี่คือหน้าเว็บที่ V2-PLAN.md ระบุว่าเป็น "★ หน้าหลักของ SEO" และเป็นเหตุผลหลักที่ทำ v2 ทั้งโปรเจกต์ (เพื่อให้ Google Images เห็นรูปสินค้า) — ตอนนี้ **ทุกหน้าหมวดหมู่แสดงไอคอนรูปพังทั้งหมด** ทั้งกระทบ SEO เต็มๆ และทำให้ลูกค้าที่คลิกจาก Google เข้ามาเจอหน้าที่ดูเหมือนพัง

**ข้อเสนอแนะ:** แก้ script ที่ generate หน้าหมวดหมู่ (build script) ให้ใส่ `../../` นำหน้า path รูปสินค้าในการ์ดทุกจุด แล้ว build ใหม่ทั้ง 24 หน้า

### 2. ลิงก์ "หมวดหมู่สินค้า" (`?cat=`) ทั่วทั้งเว็บใช้งานไม่ได้เลย
**พบใน:** การ์ด Showcase หน้าแรก (5 จุด) + footer ทุกหน้า (index.html, products.html, branches.html, gallery.html, about.html — หน้าละ 5 จุด) รวม ~25+ จุดทั่วเว็บ

**สาเหตุ:**
- `js/products.js` **ไม่มีโค้ดอ่านค่า query string `?cat=` เลย** (ไม่มี `URLSearchParams` ในทั้งโปรเจกต์)
- ค่าหมวดหมู่ที่ใช้ในลิงก์ (`โคมไฟภายนอก`, `แชนเดอเลียร์`, `หลอด LED` ฯลฯ) **ไม่ตรงกับชื่อหมวดหมู่จริงใน `data/products.json`/`js/data.js`** เลยสักตัว ทั้งไม่ตรงกับหมวดจริง (24 หมวด) และไม่ตรงกับชื่อกลุ่มใหญ่ใน `CATEGORY_TREE` (`Exterior Lamp`, `Interior Lamp`, `Chandelier`, `LED`, `Bulb Accessories`)

**ทดสอบจริงแล้ว:** เข้า `products.html?cat=แชนเดอเลียร์` → เว็บโชว์สินค้าทั้งหมดแบบไม่กรอง เริ่มด้วย "GARDEN LAMP โคมไฟสนาม" ไม่มี filter chip ขึ้นเลย

**ผลกระทบ:** ลูกค้าคลิก "Chandelier / Exterior Lamp" จากหน้าแรกหรือ footer เพื่อดูเฉพาะหมวดที่สนใจ จะเจอสินค้าทั้ง 792 ชิ้นปนกันหมด ดูเหมือนเว็บพัง ทำให้ลูกค้าหลุดจากเว็บ

**ข้อเสนอแนะ:** เขียนโค้ดอ่าน `?cat=` ใน products.js และแก้ค่า category ในลิงก์ทุกจุดให้ตรงกับชื่อกลุ่มใหญ่ใน `CATEGORY_TREE` จริง

## 🟡 Medium — Accessibility / มาตรฐานเว็บ

### 8. องค์ประกอบที่คลิกได้ใช้ `<div>` เปล่าแทนปุ่ม/ลิงก์จริง
- `.branch-mini-card` (branches.html), `.promo-card` (index.html), `.product-card` (products.js)
- ไม่มี `tabindex`, `role="button"`, หรือ keyboard handler → ผู้ใช้คีย์บอร์ด/screen reader ใช้งานไม่ได้ (ไม่ผ่าน WCAG 2.1 — 2.1.1 Keyboard)

**ข้อเสนอแนะ:** เปลี่ยนเป็น `<button type="button">` หรือเพิ่ม `role="button" tabindex="0"` พร้อม keydown handler

### 9. รูปสินค้าในแคตตาล็อกหลัก (products.html) ใช้ CSS `background-image` แทน `<img>`
ใน `js/products.js` (renderProducts / openModal) รูปสินค้าใส่ผ่าน `style="background-image:url(...)"` — ไม่มี `alt` text, ไม่มี `width/height`

**ผลกระทบ:** ขัดกับ spec ของโปรเจกต์เอง (V2-PLAN.md หมวด 6 กำหนดให้ใส่ alt + width/height + lazy ทุกรูป) Google Images มองไม่เห็นรูป, screen reader อ่านไม่ได้ — (ข้อสังเกต: หน้าหมวดหมู่ 24 หน้าทำถูกแล้ว ใช้ `<img alt>` จริง มีแค่หน้า products.html หลักที่ยังใช้ background-image)

**ข้อเสนอแนะ:** เปลี่ยนเป็น `<img src=".." alt="{ชื่อสินค้า}" loading="lazy" width height>`

### 10. ปุ่มเมนูมือถือ (`#navToggle`) ไม่มี `aria-expanded`
ทดสอบจริงบนหน้าจอมือถือ (375px): กดปุ่มแล้วเมนูเปิดได้ปกติ (`display: none → flex`) แต่ไม่มี attribute `aria-expanded="true/false"` เปลี่ยนตามสถานะ → ผู้ใช้ screen reader ไม่ทราบว่าเมนูเปิดอยู่หรือปิดอยู่

**ข้อเสนอแนะ:** เพิ่ม `aria-expanded` toggle คู่กับ class `open` ใน JS ทุกหน้า

## 🟢 Low — จุดเล็กน้อย

### 11. `rel` attribute ไม่สม่ำเสมอ
ลิงก์ `target="_blank"` บางจุดมีแค่ `rel="noopener"` บางจุดมี `rel="noopener noreferrer"` — ควรใช้มาตรฐานเดียวกันทั้งเว็บ

### 12. Google Maps link ไม่ผ่าน `encodeURIComponent()`
`branches.html` แทรกข้อความไทย + `+` ตรงๆ ใน URL — ปัจจุบันใช้งานได้เพราะเบราว์เซอร์ auto-encode ให้ แต่เป็น pattern เปราะบาง

### 13. คุณภาพข้อมูลสินค้าบางรายการพิมพ์ตกอักษร (ติดมาจากข้อมูล migration เดิม)
เช่น สินค้ารหัส `05-881-BK` ชื่อในข้อมูลคือ `"ฟหัวเสา #05-881-BK"` (ตกตัว "ไ" — ที่ถูกควรเป็น "ไฟหัวเสา") พบใน `data/products.json` โดยตรง ไม่ใช่บั๊กโค้ด แต่เป็นความสะอาดของข้อมูลที่ scrape มา

**ข้อเสนอแนะ:** ถ้ามีเวลา ควรสุ่มตรวจชื่อสินค้าทั้งหมดเทียบกับหน้าเว็บเก่าอีกรอบ (ไม่จำเป็นต้องแก้ตอนนี้)

### 14. ไม่มีหน้า 404 กำหนดเอง
GitHub Pages จะโชว์ 404 default ของ GitHub เวลาเข้า path ที่ไม่มี — ไม่ critical แต่ปรับปรุง UX ได้ถ้ามีเวลา
